1. Σκοπός

Το EscapeHub είναι μια πλατφόρμα συνεργατικών αποστολών μυστηρίου τύπου escape room. Οι χρήστες συμμετέχουν ατομικά
ή σε ομάδες, εξερευνούν μη γραμμικές διαδρομές, συλλέγουν στοιχεία σε κοινό ημερολόγιο και επιλύουν
γρίφους χρησιμοποιώντας πραγματικά δεδομένα από τα Wikidata και το Open Library.

2. Μέθοδος ιεράρχησης

Προτεραιότητα          Περιγραφή

Must Have              Απαραίτητες λειτουργίες για τη βασική έκδοση του MVP.

Should Have            Σημαντικές λειτουργίες που πρέπει να υλοποιηθούν, εφόσον το επιτρέπουν οι διαθέσιμοι πόροι.

Could Have             Πρόσθετες λειτουργίες που βελτιώνουν την εμπειρία χρήσης.

Won't Have (MVP)       Λειτουργίες που δεν περιλαμβάνονται στην αρχική έκδοση.


3. Product Backlog

PB-01 – Εγγραφή και σύνδεση χρηστών
Ιστορία χρήστη:
Ως χρήστης θέλω να μπορώ να δημιουργήσω λογαριασμό και να συνδεθώ στην πλατφόρμα, ώστε να συμμετέχω στις αποστολές.

Κριτήρια αποδοχής:
1. Ο χρήστης μπορεί να δημιουργήσει λογαριασμό με τα απαιτούμενα στοιχεία.
2. Ο χρήστης μπορεί να συνδεθεί με έγκυρα στοιχεία.
3. Το σύστημα απορρίπτει μη έγκυρα στοιχεία σύνδεσης.
4. Τα δεδομένα λογαριασμού αποθηκεύονται με ασφάλεια.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-02 – Δημιουργία και συμμετοχή σε ομάδες
Ιστορία χρήστη:
Ως χρήστης θέλω να μπορώ να δημιουργήσω ομάδα ή να συμμετέχω σε υπάρχουσα ομάδα, ώστε να συνεργάζομαι με άλλους παίκτες.

Κριτήρια αποδοχής:
1. Ένας χρήστης μπορεί να δημιουργήσει ομάδα.
2. Ένας χρήστης μπορεί να συμμετέχει σε ομάδα.
3. Το σύστημα καταγράφει τα μέλη κάθε ομάδας.
4. Τα μέλη της ομάδας μπορούν να συμμετέχουν στην ίδια αποστολή.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-03 – Επιλογή και έναρξη αποστολής
Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να επιλέγω και να ξεκινώ μια αποστολή, ώστε να συμμετέχω στην ιστορία μυστηρίου.

Κριτήρια αποδοχής:
1. Εμφανίζεται διαθέσιμη αποστολή.
2. Ο παίκτης μπορεί να επιλέξει και να ξεκινήσει την αποστολή.
3. Το σύστημα καταγράφει την έναρξη και την πρόοδο.
4. Η αποστολή συσχετίζεται με τον αντίστοιχο χρήστη ή την ομάδα.

Προτεραιότητα: Must Have
Εκτίμηση: 3 Story Points

PB-04 – Εξερεύνηση μη γραμμικών διαδρομών
Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να εξερευνώ διαφορετικές διαδρομές μιας αποστολής, ώστε να ανακαλύπτω στοιχεία με 
διαφορετική σειρά.

Κριτήρια αποδοχής:
1. Μια αποστολή υποστηρίζει περισσότερες από μία διαδρομές.
2. Ο παίκτης μπορεί να επιλέγει μεταξύ διαθέσιμων διαδρομών.
3. Η εξέλιξη της αποστολής δεν απαιτεί μία μοναδική προκαθορισμένη σειρά.
4. Το σύστημα καταγράφει τις διαδρομές που έχουν εξερευνηθεί.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-05 – Συλλογή και αποθήκευση στοιχείων
Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να συλλέγω στοιχεία κατά τη διάρκεια μιας αποστολής, ώστε να συγκεντρώνω τις απαραίτητες 
πληροφορίες για την επίλυση των γρίφων.

Κριτήρια αποδοχής:
1. Ο παίκτης μπορεί να συλλέγει διαθέσιμα στοιχεία.
2. Κάθε στοιχείο συσχετίζεται με την αντίστοιχη αποστολή.
3. Τα στοιχεία αποθηκεύονται στη βάση δεδομένων.
4. Ο παίκτης μπορεί να βλέπει τα στοιχεία που έχει ήδη συλλέξει.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-06 – Κοινό ημερολόγιο στοιχείων ομάδας
Ιστορία χρήστη:
Ως μέλος μιας ομάδας θέλω να βλέπω τα στοιχεία που συλλέγουν τα υπόλοιπα μέλη, ώστε να συνεργαζόμαστε στην επίλυση της 
αποστολής.

Κριτήρια αποδοχής:
1. Κάθε ομάδα διαθέτει κοινό ημερολόγιο στοιχείων.
2. Τα στοιχεία που συλλέγει ένα μέλος εμφανίζονται στο κοινό ημερολόγιο.
3. Τα μέλη της ίδιας ομάδας μπορούν να βλέπουν τα διαθέσιμα στοιχεία.
4. Τα δεδομένα διαφορετικών ομάδων παραμένουν διαχωρισμένα.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-07 – Υπό όρους αποκάλυψη στοιχείων
Ιστορία χρήστη:
Ως παίκτης θέλω ορισμένα στοιχεία να αποκαλύπτονται μόνο όταν ικανοποιούνται συγκεκριμένες προϋποθέσεις, ώστε να 
διατηρείται η εξέλιξη και η δυσκολία της αποστολής.

Κριτήρια αποδοχής:
1. Τα στοιχεία μπορούν να έχουν προϋποθέσεις αποκάλυψης.
2. Το σύστημα ελέγχει αν έχουν ικανοποιηθεί οι προϋποθέσεις.
3. Τα στοιχεία εμφανίζονται όταν πληρούνται οι απαραίτητοι κανόνες.
4. Δεν εμφανίζονται στοιχεία των οποίων οι προϋποθέσεις δεν έχουν ικανοποιηθεί.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-08 – Διαχείριση και επίλυση γρίφων
Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να επιλύω διαφορετικούς γρίφους κατά τη διάρκεια της αποστολής, ώστε να προχωρώ στην ιστορία.

Κριτήρια αποδοχής:
1. Η εφαρμογή υποστηρίζει διαφορετικές κατηγορίες γρίφων.
2. Ο παίκτης μπορεί να υποβάλει απάντηση.
3. Το σύστημα ελέγχει την εγκυρότητα της απάντησης.
4. Καταγράφονται οι προσπάθειες επίλυσης.

Η επιτυχής επίλυση μπορεί να ξεκλειδώνει επόμενα στάδια ή στοιχεία.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-09 – Συνεργατικοί γρίφοι
Ιστορία χρήστη:
Ως μέλος ομάδας θέλω να μπορώ να συμμετέχω σε γρίφους που απαιτούν τη συνεργασία περισσότερων παικτών, ώστε η λύση να 
προκύπτει από τη συνεισφορά της ομάδας.

Κριτήρια αποδοχής:
1. Υποστηρίζονται γρίφοι που απαιτούν περισσότερους από έναν παίκτες.
2. Κάθε συμμετέχων μπορεί να συνεισφέρει την απαιτούμενη πληροφορία.
3. Το σύστημα ελέγχει αν έχουν συγκεντρωθεί οι απαραίτητες συνεισφορές.
4. Ο γρίφος ολοκληρώνεται όταν ικανοποιούνται οι απαιτήσεις συνεργασίας.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-10 – Ενσωμάτωση Wikidata API

Ιστορία χρήστη:
Ως παίκτης θέλω η εφαρμογή να αξιοποιεί πληροφορίες από το Wikidata, ώστε να χρησιμοποιώ πραγματικά δεδομένα κατά την 
εξερεύνηση και επίλυση γρίφων.

Κριτήρια αποδοχής:
1. Η εφαρμογή μπορεί να επικοινωνεί με το Wikidata API.
2. Μπορεί να ανακτά τις απαιτούμενες πληροφορίες.
3. Οι αποκρίσεις ελέγχονται πριν χρησιμοποιηθούν.
4. Η εφαρμογή χειρίζεται σφάλματα επικοινωνίας.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-11 – Ενσωμάτωση Open Library API
Ιστορία χρήστη:
Ως παίκτης θέλω η εφαρμογή να αξιοποιεί πληροφορίες από το Open Library, ώστε να χρησιμοποιώ δεδομένα βιβλίων και 
συγγραφέων στους γρίφους.

Κριτήρια αποδοχής:
1. Η εφαρμογή μπορεί να επικοινωνεί με το Open Library API. 
2. Μπορεί να αναζητά πληροφορίες βιβλίων και συγγραφέων.
3. Οι αποκρίσεις ελέγχονται πριν χρησιμοποιηθούν.
4. Η εφαρμογή χειρίζεται σφάλματα επικοινωνίας.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-12 – Συνδυασμός πληροφοριών από εξωτερικές πηγές

Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να αξιοποιώ πληροφορίες από διαφορετικές πηγές, ώστε να συνδυάζω στοιχεία για την επίλυση
πιο σύνθετων γρίφων.

Κριτήρια αποδοχής:
1. Το σύστημα μπορεί να αξιοποιεί δεδομένα από τα Wikidata και το Open Library.
2. Οι πληροφορίες μπορούν να συσχετίζονται στο πλαίσιο μιας αποστολής.
3. Οι συνδυασμένες πληροφορίες είναι διαθέσιμες για τη λογική των γρίφων.

Προτεραιότητα: Must Have
Εκτίμηση: 8 Story Points

PB-13 – Snapshots και διαχείριση αποτυχιών APIs

Ιστορία χρήστη:
Ως ομάδα ανάπτυξης θέλουμε να διαχειριζόμαστε αποτυχίες εξωτερικών APIs και να χρησιμοποιούμε αποθηκευμένα snapshots,
ώστε η εφαρμογή και οι αυτοματοποιημένοι έλεγχοι να λειτουργούν αξιόπιστα.

Κριτήρια αποδοχής:
1. Υπάρχει χειρισμός αποτυχιών επικοινωνίας με εξωτερικά APIs.
2. Μπορούν να χρησιμοποιηθούν αποθηκευμένα snapshots ή fixtures.
3. Τα tests δεν εξαρτώνται υποχρεωτικά από ζωντανές κλήσεις APIs.
4. Η εφαρμογή διαχειρίζεται κατάλληλα μη έγκυρες ή ελλιπείς αποκρίσεις.

Προτεραιότητα: Must Have
Εκτίμηση: 5 Story Points

PB-14 – Ολοκλήρωση αποστολής και καταγραφή χρόνου

Ιστορία χρήστη:
Ως παίκτης θέλω να μπορώ να ολοκληρώνω μια αποστολή και να βλέπω τον χρόνο που χρειάστηκα, ώστε να παρακολουθώ 
την επίδοσή μου.

Κριτήρια αποδοχής:
1. Το σύστημα αναγνωρίζει την ολοκλήρωση της αποστολής.
2. Καταγράφεται ο χρόνος έναρξης και ολοκλήρωσης.
3. Υπολογίζεται ο συνολικός χρόνος ολοκλήρωσης.
4. Η κατάσταση ολοκλήρωσης αποθηκεύεται.

Προτεραιότητα: Must Have
Εκτίμηση: 3 Story Points

PB-15 – Συγχρονισμός ενημερώσεων ομάδας

Ιστορία χρήστη:
Ως μέλος ομάδας θέλω οι ενημερώσεις που αφορούν την πρόοδο και τα συλλεγμένα στοιχεία να είναι διαθέσιμες στα υπόλοιπα
μέλη, ώστε να διατηρείται κοινή εικόνα της αποστολής.

Κριτήρια αποδοχής:
1. Οι ενημερώσεις της ομάδας αποθηκεύονται με συνέπεια.
2. Τα μέλη βλέπουν την ενημερωμένη κατάσταση της αποστολής.
3. Δεν χάνονται ή αντικαθίστανται λανθασμένα ενημερώσεις από διαφορετικά μέλη.

Προτεραιότητα: Should Have
Εκτίμηση: 5 Story Points
